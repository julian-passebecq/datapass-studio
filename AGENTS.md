# Rules for continuing this repository

Read README, docs/ARCHITECTURE.md, docs/TEST_REPORT.md and docs/NEXT_PASS.md first.

1. FOIL is an optional private consumer, never a dependency of `packages/` or a scientific authority inside the app shell. Do not commit `.private/`, `public/private-client/`, `dist-private/`, private screenshots, private offline HTML or source reference artifacts.
2. Never promote prescribed/synthetic/screening data to measured or scientifically validated evidence. Preserve reference hashes and source/candidate distinction. Mesh preview is not BRep/STEP regeneration.
3. Domain inputs, session selection, high-frequency playback and backend results have separate ownership. A late response cannot overwrite a newer request or parameter revision. A view event must not trigger scientific computation.
4. Do not put executable expressions in serialized documents. Imported JSON is inert and validated. Python handlers are allowlisted, trusted source registrations. Do not add arbitrary exec/eval/SQL/shell endpoints.
5. Reuse the existing ConceptMotion/Fluent packages through their pinned external-consumer contract. Do not build a second ConceptMotion core or claim native HTML controls are official Fluent. D3 analytical charts remain a sibling renderer, not an expansion of ConceptMotion semantics.
6. DiagramCloud stays separate. No new producer format may masquerade as its supported importer. Adapt exported evidence explicitly with provenance and review.
7. Keep three truth levels separate in reporting: implemented code; checks actually run; guarantees not yet qualified. Local isolated DOM checks do not prove HTTP, IndexedDB, GPU WebGL or hosted CI. Workflow configuration is not a green workflow result.
8. Test changes using Node, Python, schema drift/boundary checks and actual browser interaction. Screenshots must come from the running app. Do not hide render errors to create prettier evidence.
9. Release public assets through an allowlist. The public build excludes the private client by default. Review privacy before updating the branch or producing a public deployment.
10. Do not merge a feature branch automatically. Preserve the initial repository and open a reviewable PR.
